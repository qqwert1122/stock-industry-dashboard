# 설계 문서 — 투자자별 수급 전체 분해 (11주체 × 주식/선물 × 매도/매수/순매수)

상태: **확정 (2026-07-08 오너 결정)** — 매도/매수/순매수 **전부 정식 지표화** (아래 5절 A안 채택).
지표 수 증가에 따른 탐색 문제는 매트릭스 뷰(4-3, 폐기)가 아니라
**전역 지표 검색 기능**([feature-metric-search.md](feature-metric-search.md))으로 해결한다.
B2-①(feat/b2-flows)이 진행 중이므로 track-b-market-overview.md / agent-prompts.md는 수정하지 않는다.
이 문서를 근거로 **B2-③ 후속 Phase**로 실행한다 (실행 프롬프트는 7절).

## 1. 요구

11개 투자주체 — 개인, 외국인, 기관종합, 금융투자, 보험, 투신, **기타금융**, 은행, 연기금, 사모, 기타법인 —
에 대해 주식(KOSPI/KOSDAQ)과 선물 각각 **매도/매수/순매수** 지표 추가.

기존 B2-1 설계와의 차이:
- B2-1은 이미 10주체(기타금융 제외) × KOSPI/KOSDAQ **순매수**를 계획에 포함
- 신규 요소는 ① **기타금융** 추가 ② **매도/매수 총액**(그로스) ③ **선물의 전 주체 분해**
  (B2-1은 선물을 외국인/기관만 계획)

## 2. 데이터 가용성 — 가능, 추가 호출 비용 0

- KRX 투자자별 거래실적(주식, bld 후보 `MDCSTAT02203`)은 **한 번의 호출 응답에 11주체 전체의
  매도/매수/순매수(거래대금·거래량)가 행으로 모두 포함**된다. 즉 주체·측정값을 늘려도
  API 호출 수는 B2-1과 동일 (시장당 일 1회). 파싱만 늘어난다.
- 선물(파생 투자자별, bld 후보 `MDCSTAT13502` 계열)도 유사한 주체 분해를 제공하나,
  **주체 구분이 주식과 완전히 일치하는지(특히 사모·기타금융) ⚠️ 구현 시 검증 필요.**
  상품은 KOSPI200 선물로 한정한다 (미니/옵션 확대는 범위 밖).

## 3. 설계 쟁점 — 지표 수 폭발

전부 정식 지표로 만들면: 주식 11주체 × 2시장 × 3측정 = 66개 + 선물 11 × 3 = 33개 → **+99개**
(현재 전체 지표가 158개). 문제:

| 영향 | 평가 |
|---|---|
| 수급 탭 UI | 지표 테이블 99행 — 탐색 불가능한 스크롤. **최대 쟁점** |
| dashboard.json 크기 | 지표당 히스토리 60pt 포함 ≈ +수백 KB — 허용 범위지만 낭비 |
| data/history 파일 수 | +99개 — 기술적으로 문제없음 |
| AI 카드 프롬프트 | 지표 나열형 컨텍스트가 커져 토큰 낭비 + 요점 희석 |
| 정보 가치 | **순매수가 신호의 전부에 가깝다.** 매도/매수 그로스는 "참여 강도" 확인용 보조 정보로,
  독립 히스토리·차트를 가질 만한 가치가 낮다 |

## 4. 확정 설계 — 전부 지표화 + 검색으로 탐색 (2026-07-08 개정)

### 4-1. 지표화 범위

**매도/매수/순매수 전부** 정식 지표(히스토리·차트·퍼센타일 대상)로 만든다:
- 주식: 11주체 × KOSPI/KOSDAQ × 3측정 = **66개**
- 선물(K200): KRX 제공 주체 분류 전체 × 3측정 = **최대 33개** (⚠️ 주체 분류 검증 후 확정)
- 합계 최대 99개. 단위는 억원(거래대금 기준), 거래량은 이번 범위에서 제외.

### 4-2. 지표 구조 (기존 depth/group 체계로 정리)

수급 탭 안에서 3단으로 배치해 표 구조 자체는 현행 UI 문법을 유지한다:
- `depth` = 시장 (KOSPI / KOSDAQ / K200 선물)
- `group` = 주체 (개인, 외국인, 기관종합, 금융투자, 보험, 투신, 기타금융, 은행, 연기금, 사모, 기타법인)
- 행 = 매도 / 매수 / 순매수 (3행 테이블 × 주체 그룹)
- 차트: 순매수는 `chart_style:"flow_bars"`(막대+20일 누적선), 매도/매수는 기존 라인 스파크라인.
- id·history_key 네이밍: `krx-flow-{market}-{investor}-{measure}` (예: `krx-flow-kospi-pension-net`).

### 4-3. 지표 수 증가의 부작용 통제

- **탐색**: 전역 지표 검색 기능으로 해결 — 별도 설계 [feature-metric-search.md](feature-metric-search.md).
  (기존 검토안의 매트릭스 요약 컴포넌트는 **폐기**. 검색이 같은 문제를 더 일반적으로 푼다.)
- **AI 카드 프롬프트**: 수급 지표는 **순매수만, 그중 외국인·기관종합·개인 + 절대값 상위 1~2주체**만
  요약해 전달한다. 매도/매수 그로스 지표는 AI 컨텍스트에서 항상 제외 (briefing.py에 필터 규칙).
- **dashboard.json 크기**: +99지표 × 히스토리 60pt ≈ +300~400KB 예상. AC에 상한 700KB를 둔다.
  초과 시 수급 지표만 히스토리 30pt로 축소(상세 차트는 long_history.json이 담당하므로 손실 없음).
- **텔레그램 주간 다이제스트·top_movers**: 매도/매수 그로스는 변동률 순위에서 제외
  (순매수와 중복 신호 방지).

### 4-4. 진행 중인 B2-①과의 조정 (중요)

B2-① 에이전트의 작업을 중단시키지 않는다. 단, **백필을 두 번 하지 않도록** 다음 한 가지만
진행 중인 에이전트에게 보충 지시로 전달할 가치가 있다:

> KRX 투자자별 거래실적 응답을 파싱할 때, 지표로 만들지 않는 주체·측정값을 버리지 말고
> **일자별 원본 행 전체를 스냅샷(JSON)으로 `data/history/krx-flow-raw-{market}.json`에 저장**해줘
> (market_sentiment.py의 snapshot document 패턴 재사용). 지표 확장은 후속 Phase에서 이 raw를 읽어 처리한다.

이 한 줄이 반영되면 B2-③은 API 재백필 없이 raw 재처리만으로 22+11개 지표를 만들 수 있다.
반영이 늦어 이미 순매수만 저장하는 구조로 머지되더라도, KRX 백필(하루 N일 증분)을 한 번 더
도는 것뿐이라 복구 불가능한 문제는 아니다.
