## B1. 상위 네비게이션 2단화: [시황 | 지표]

### 정보 구조

```
루트 메뉴 (사이드바 최초 상태)
├─ 시황   ── 클릭 → [← 뒤로] + 시황 하위 메뉴
│           ├─ 종합          (지수·환율·미 지수선물·K200선물 베이시스 + 게이지)
│           ├─ 수급          (투자자별 매매동향 — 핵심, B2에서 가장 상세)
│           ├─ 신용·예탁금   (신용융자잔고, 고객예탁금, 공매도, 미국 FINRA 마진)
│           ├─ 금리·채권     (한/미 국채금리, 장단기 기울기, 신용 스프레드, 기준금리, 한미 금리차)
│           ├─ 원자재·크립토 (유가·천연가스·금·구리·달러인덱스 / BTC·ETH·김치프리미엄·스테이블코인)
│           ├─ 심리·변동성   (한국 F&G, CNN F&G, VKOSPI, VIX, ADR, 52주 신고/신저, 엔캐리 모니터)
│           └─ 밸류에이션    (KOSPI/KOSDAQ PER·PBR·배당수익률, S&P500 PER/CAPE)
└─ 지표   ── 클릭 → [← 뒤로] + 현행 산업 목록 (반도체 … 매크로, 현행 UI 그대로)
```

구분 원칙: **시황 = 시장 그 자체(가격·수급·심리·밸류에이션)**, 지표>매크로 = 실물 경기
(실업률, Sahm, GDPNow, CPI/PCE, M2, 한국 CCSI·선행지수·BSI 등은 매크로 산업에 남긴다).

### 구현 방침 (`templates/dashboard.html` — 클라이언트 렌더)

- 페이로드에 새 필드 `metric.section: "market" | "industry"` 를 도입한다.
  **필드가 없는 지표는 `industry` 로 간주** (하위 호환 — 구 페이로드도 그대로 동작).
- 시황 지표는 `industry` 자리에 하위 메뉴명(`수급` 등)이 아니라 `market_category` 필드를 쓴다:
  `metric.market_category: "종합"|"수급"|"신용·예탁금"|"심리·변동성"|"밸류에이션"`.
  기존 `depth`/`group` 은 시황에서도 동일 의미로 재사용 (표 그룹핑 로직 재사용 목적).
- 사이드바 상태 머신: `level: "root" | "market" | "industry"` + 선택 항목.
  - root: [시황] [지표] 두 버튼 (아이콘 포함, 기존 메뉴 버튼 스타일 재사용)
  - market/industry 레벨: 최상단 `← ` 버튼 → root 복귀
  - 마지막 위치를 localStorage에 기억 (`dashboard-nav-state`), 최초 방문 기본값은 `시황 > 종합`
  - 기존 기능(산업 순서 드래그 정렬, 즐겨찾기) 은 지표 레벨에서 그대로 유지
- 본문 렌더: 시황 하위 메뉴 선택 시에도 **현행 산업 화면과 동일한 컴포넌트**(그룹 헤더 + 지표 테이블 +
  디테일 패널 + 스파크라인)를 사용한다. 새 레이아웃을 만들지 말 것 — "현재 디자인·양식과 비슷하게"가 요구사항.
- `시황 > 종합` 상단에는 기존 market_gauges(온도계·Fear&Greed·침체 시그널) 카드를 이동 배치
  (현재 위치에서 시황 종합 탭으로 — 지표 탭에서는 숨김).

## B2. 시황 데이터 수집 — 무료 소스 전수 + 수급 최상세

### 원칙
- 전부 무료·무계약 소스. 이미 발급된 키(ECOS, KRX open API, FRED, data.go.kr) 우선 활용.
- 비공식 엔드포인트(KRX 정보데이터시스템, Naver)는 **일 1회, 보수적 간격**으로만 호출하고
  반드시 폴백 경로를 둔다. `http_client.py` 의 기존 간격(data.krx.co.kr 2.0s)을 준수.
- 모든 신규 지표는 기존 metric 스키마 + `section:"market"` 로 편입 →
  히스토리 축적(`data/history/`), 퍼센타일, 스파크라인, fetch_log(Track A1)를 공짜로 얻는다.

### B2-1. 수급 (최우선, 가장 상세) — 새 모듈 `market_flows.py`

**소스: KRX 정보데이터시스템 비공식 JSON** `http://data.krx.co.kr/comm/bldAttendant/getJsonData.cmd`
(POST form, 키 불필요. bld 코드는 웹 화면의 XHR와 동일. ⚠️ **구현 시 실제 호출로 bld 코드·필드명 검증 필수** —
아래 코드는 후보이며 변경 가능성 있음.)

| 지표군 | bld 후보 | 산출 지표 |
|---|---|---|
| 투자자별 거래실적(주식) | `dbms/MDC/STAT/standard/MDCSTAT02203` (일별·시장별) | KOSPI/KOSDAQ × {개인, 외국인, 기관합계, 금융투자, 투신, 연기금, 보험, 사모, 은행, 기타법인} 일별 순매수대금(억원) |
| 투자자별 거래실적(선물) | `dbms/MDC/STAT/standard/MDCSTAT13502` 계열 | KOSPI200 선물 외국인/기관 순매수 계약·대금 |
| 프로그램매매 동향 | `dbms/MDC/STAT/standard/MDCSTAT090*` 계열 | KOSPI 프로그램 순매수(차익/비차익) |

- 대안/폴백 (bld 검증 실패 또는 차단 시): Naver 금융
  `finance.naver.com/sise/investorDealTrendDay.naver` HTML 파싱 (외국인/기관/개인 3분류만 제공 —
  세부 기관 분류는 포기하고 3분류로 축소 운영).
- 표시 설계 (수급을 "특히 자세하게"):
  - `수급` 탭 그룹 구성:
    - `외국인` — KOSPI 순매수, KOSDAQ 순매수, 선물 순매수, (가능 시) 외국인 시가총액 보유비중
    - `기관` — 기관합계, 연기금, 금융투자, 투신 (KOSPI 기준 + KOSDAQ 합계)
    - `개인` — KOSPI/KOSDAQ 순매수
    - `프로그램` — 차익/비차익 순매수
  - 디테일 패널 확장: 수급 지표는 **일별 막대(순매수) + 누적선(20영업일 누적)** 차트가 필요.
    metric에 `chart_style: "flow_bars"` 힌트 필드 추가, 프론트 스파크라인 렌더에 막대 모드 구현.
  - 파생 요약 지표(계산): `외국인 20일 누적 순매수`, `기관 20일 누적 순매수` — 추세 판단용.
- 히스토리: `data/history/krx-flow-*.json`. 최초 백필은 KRX 화면 조회 한도 내에서 과거 2년을
  **하루 N일씩 증분 백필** (market_sentiment.py의 `max_backfill_days_per_run` 패턴 재사용).
- 수집 주기: **일 1회, 풀빌드에서만** (확정치는 장 마감 후 산출). 관측일 지연(T+0 저녁 확정)을
  `observed_label` 에 정확히 반영.

엔캐리 청산은 "저금리 엔을 빌려 고금리 자산에 투자한 포지션"이 일시에 풀리는 이벤트로,
글로벌 위험자산(코스피 포함) 급락의 트리거가 된다 (2024-08-05가 대표 사례).
가격(엔달러)만 보면 이미 늦으므로, **포지션·금리차·변동성을 묶어 한 그룹**으로 감시한다.

| 지표 | 소스 | 주기 | 청산 감지에서의 역할 |
|---|---|---|---|
| **엔/달러 환율 (USD/JPY)** | Yahoo `JPY=X` (intraday, 기존 수집기 재사용). 장기 백필은 FRED `DEXJPUS`(1971~) ⚠️ 병합 방식 검증 | intraday | 급락(엔 급등)이 청산 진행의 실시간 신호. `시황>종합` 환율 그룹에도 병행 노출 |
| **엔/원 재정환율 (JPY/KRW)** | Yahoo `JPYKRW=X` ⚠️ 심볼 검증, 폴백: KRW=X ÷ JPY=X 계산 | intraday | 원화 대비 엔 강세 = 국내 증시 외국인 수급에 직접 영향 |
| **CFTC 엔 투기적 순포지션** | CFTC Public Reporting API `publicreporting.cftc.gov` (Socrata JSON, 무키·무료). Legacy COT의 JPY 선물(CME) 비상업 순포지션 = long − short. ⚠️ 계약코드(후보 `097741`)·필드명 구현 시 검증. `HOST_MIN_INTERVALS` 등록 | **주간** (화요일 기준, 금요일 발표 — `observed_at` 에 기준일 명시) | **가장 중요한 선행지표.** 대규모 넷숏 = 캐리 포지션 누적(위험 축적), 넷숏의 급격한 축소/롱 전환 = 청산 진행 |
| **미일 10년 금리차** | 계산: FRED `DGS10`(기존) − 일본 10년 JGB 금리 | 일간 | 캐리의 원천 수익. 축소가 빠르면 포지션 청산 유인 증가 |
| **일본 10년 국채금리** | 일본 재무성(MOF) 금리 CSV(일간, 무료) ⚠️ URL·포맷 검증, 폴백 FRED `IRLTLT01JPM156N`(월간, 지연) | 일간 | BOJ 긴축 전환 감시. 미일 금리차의 다리 |
| **엔 환율 실현변동성 (10일)** | 계산: JPY=F 아님, `JPY=X` 일별 히스토리 기반 (market_sentiment.py 의 `rolling_realized_volatility` 재사용) | 일간 | 변동성 급등 = 청산 가속 국면. 추가 호출 0 |

- 일본 단기금리(`IRSTCI01JPM156N`, 월간)는 이미 매크로 산업에 수집 중 — 병행 노출로 이 그룹에 표시.
- **텔레그램 알림은 두지 않는다** (2026-07-08 오너 결정): 엔캐리는 수개월 축적 → 2~3거래일 급성기
  패턴이라 징조는 사이트의 지표·배지로 충분하고, 급성기 진입은 뉴스가 더 빠르다.
  이에 따라 변화율 알림 룰 타입(`change_5d_pct_below` 등)도 **구현 범위에서 제외** —
  감시는 아래 해석 연계(그룹 배지)와 AI 카드 언급(Track A3)으로만 한다.
- **해석 연계** (B3): 엔캐리 그룹 전용 문구 템플릿 — 예: "투기적 엔 넷숏이 10년 상위 5% 수준으로
  쌓여 있습니다. 포지션이 한 방향으로 몰릴수록 급격한 되감기 위험이 커집니다."
  단일 지표가 아니라 **그룹 요약 배지**(포지션 누적/중립/청산 진행 3단계)를 심리·변동성 탭 상단에 표시:
  판정식 = 넷숏 퍼센타일(누적도) × USD/JPY 단기 변화(트리거) × 실현변동성(가속) 룰 조합, `interpretation.py` 에 구현.

## B3. 지표 해석 레이어 — 계산식 기반 의미 매핑 (AI 불요)

### 목표
AI 카드 없이도, 각 지표 디테일에서 "이 값이 지금 어떤 의미인지"를 규칙 기반으로 보여준다.
기존 자산: `meaning`(정의 텍스트), `percentiles`(window_stats, 10년 퍼센타일 등), YoY, 변화율.

### 설계 — 새 모듈 `interpretation.py`

빌드 시 각 지표에 `interpretation` 객체를 계산해 부여:

```json
"interpretation": {
  "zone": "hot | warm | neutral | cool | cold",     // 색상 매핑용 (기존 게이지 팔레트 재사용)
  "level_label": "10년 범위 상위 7% — 역사적 고점권",
  "trend_label": "3개월 연속 상승, 전월 대비 +2.1%",
  "text": "하이일드 OAS가 낮을수록 위험선호가 강하다는 뜻입니다. 지금은 10년 중 하위 8% 수준으로, 신용시장이 매우 낙관적인 구간입니다."
}
```

계산 파이프라인 (모두 이미 있는 데이터로 계산):
0. **도메인 임계 zone (절대 기준, 최우선)**: 통용 기준이 있는 지표는 퍼센타일보다 임계값 매핑을
   우선 적용한다. config 규칙에 `thresholds:` 로 선언:
   ```yaml
   - match: { id: SAHMREALTIME }
     thresholds:
       - { above: 0.5, zone: hot, text: "침체가 이미 시작됐을 확률이 높다는 신호입니다." }
       - { below: 0.5, zone: neutral, text: "침체 판정 기준(0.5) 아래의 안전 구간입니다." }
   ```
   우선 등록(통용 기준이 명확한 것): Sahm(0.5), 10Y-3M·10Y-2Y(0, 역전), VIX(30/40),
   하이일드 OAS(3/5), 코스피 PBR(0.9/1.3), 원/달러(1400/1500), 김치프리미엄(±3/±7),
   BSI·CCSI(100), 경기선행지수 순환변동치(100). 임계 문구에는 **기준선 수치를 문장에 포함**
   ("기준 0.5 대비 …")해 사용자가 판정 근거를 볼 수 있게 한다.
1. **위치(level)**: 임계 규칙이 없는 지표는 `percentiles` 의 10년(가능하면 최대기간) 퍼센타일 →
   5구간 zone 매핑 (기본: ≥90 hot / 70–90 warm / 30–70 neutral / 10–30 cool / <10 cold)
2. **방향(trend)**: history 최근 포인트들로 연속 상승/하락 개월(또는 주·일) 수 + 최근 변화율
3. **극성(polarity)**: 지표마다 "높으면 좋은가"가 다르다 → config로 선언:
   ```yaml
   interpretation:
     defaults: { polarity: neutral }        # 미지정 지표는 위치·방향만 서술, 가치판단 없음
     rules:
       - match: { group: "신용 스프레드" }   # group/industry/id/name 매칭
         polarity: lower_is_better
         hot_text: "스프레드가 크게 벌어져 신용경색 우려 구간입니다."
         cold_text: "스프레드가 매우 좁아 위험선호가 강한 구간입니다."
       - match: { id: "DGS10" }
         polarity: context                  # 서술형: 방향+위치만, 좋다/나쁘다 판단 회피
   ```
4. **문장 생성**: `meaning`(정의) 1문장 + level/trend 서술 + polarity에 따른 상태 문장.
   템플릿 문자열 조합으로 생성 (LLM 호출 없음). 수급 지표(B2)는 전용 템플릿:
   "외국인이 5일 연속 순매수, 20일 누적 +1.2조원 — 수급 주체가 지수를 받치는 구간입니다."

### UI (`templates/dashboard.html` 디테일 패널)

- 디테일 패널 상단에 zone 색 배지 + level_label, 그 아래 `text` 2~3문장.
- 기존 AI 카드와 시각적으로 구분: "계산 기반 해석" 캡션 (AI 문구와 혼동 방지).
