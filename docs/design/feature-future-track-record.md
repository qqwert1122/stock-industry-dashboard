# 기능 설계 — 예측의 성적표: 과거 기술 예측 아카이브 (F6) [Tier 3]

상태: 기획 초안 (2026-07-10). 목적: **과거의 기술 예측이 실제로 언제 완성됐는지**(혹은
아직도 안 왔는지)를 보여주는 아카이브. '미래' 페이지의 타임라인이 "앞으로"라면, 이 기능은
"뒤로" — 예측이라는 행위 자체의 성적표를 보여줘서 독자가 미래 타임라인을 맹신도 냉소도
아닌 **보정된 눈**으로 읽게 만든다.

의존성: F1(feature-future-timeline.md) 머지 후. F1의 타임라인 "오늘 마커 위 달성 예측 접기"
영역을 이 기능이 정식으로 확장한다. F2~F5와 독립.

공통 제약: **운영 비용 0원.** 정적 콘텐츠 중심 — 신규 수집기 없음.

---

## 0. 사용자 교육 관점 — 왜 과거를 보여주나

일반인 독자가 미래 예측 앞에서 갖는 두 태도는 둘 다 틀렸다: "2029년에 AGI가 온대!"(맹신)와
"어차피 다 뻥이야"(냉소). 과거 성적표는 그 사이의 진실을 체감시킨다:

1. **예측은 자주 틀리지만, 방향은 대체로 맞는다** — 통신위성은 20년 만에, 게놈 프로젝트는
   예정보다 빨리, 화상통화는 예고보다 45년 늦게 왔다. "온다/안 온다"보다 "언제 오나"가
   틀리는 것이 예측의 정상 상태임을 보여준다.
2. **예측 주체마다 버릇이 있다** — 낙관하는 사람, 업계 홍보, 신중한 기관. 주체별 성적을
   보여주면 독자는 F1 타임라인의 "커즈와일은 2029년으로 예측합니다"를 스스로 보정해서 읽는다.
3. **이 페이지 자체의 정직성 장치** — 우리가 추적하는 예측도 언젠가 이 아카이브에 들어간다.
   맞으면 맞은 대로, 틀리면 틀린 대로 기록이 남는다는 것 자체가 신뢰의 근거다.

설계 원칙: F1 톤 가이드 승계(전문용어 0의 첫 문장, 과장 금지) + **조롱 금지** — 빗나간
예측을 "바보 같은 예언" 콘텐츠로 소비하지 않는다. 왜 빗나갔는지(기술은 됐는데 수요가 없었다,
규제가 막았다, 과소평가였다)가 교육 가치의 본체다.

## 1. UI

### 1.1 진입점 — 타임라인의 "과거" 구간 확장

F1 타임라인에서 오늘 마커 위에 접혀 있던 달성 예측 영역을 "예측의 성적표 →" 링크로 확장.
클릭 시 전용 뷰 `#/future/track-record`.

### 1.2 성적표 뷰 — 예측 vs 실제 덤벨 차트

행 단위 구성 (기술 하나 = 행 하나), 세로 스크롤 리스트:

```
통신위성          클라크, 1945년 예측
  예상 ●────────● 실제        1960년대 예상 → 1965 실현       [거의 정확]
화상통화 보편화    AT&T, 1964년 예측
  예상 ●━━━━━━━━━━━━━━━● 실제  "10년 내" → 2010년대(스마트폰)  [45년 늦음]
핵융합 발전       업계, 1970년대 예측
  예상 ●┄┄┄┄┄┄┄┄┄→          "2000년경" → 아직              [미완, 55년+]
```

- 가로축 = 연도. 왼쪽 점 = 예상 시점, 오른쪽 점 = 실제 시점, 선 길이 = 오차.
- 상태 색: 일찍 옴(teal) · 거의 정확 ±2년(green) · 늦음(amber) · 미완(red, 화살표가
  오른쪽 끝에서 열림) · 판정 대기(gray).
- 행 클릭 → 상세: 3문 설명(무엇을 예측했나 / 실제로는 어떻게 됐나 / **왜 빗나갔나·맞았나**)
  + 출처. "왜" 문장이 이 기능의 교육 페이로드다.
- 정렬 토글: 예측 연도순(기본) / 오차 큰 순 / 주체별.

### 1.3 예측 주체 스코어카드

뷰 상단에 주체별 요약 카드 (빌드에서 자동 계산):

- "커즈와일 — 판정 완료 12건: ±2년 적중 5건 · 평균 4년 낙관" 식의 한 줄 통계.
- 카드 클릭 시 해당 주체의 예측만 필터.
- **F1 연동 (핵심)**: F1 기술 카드의 예측 출처 옆에 이 통계를 미니 배지로 노출 —
  "커즈와일 예측 · 과거 적중 5/12". 미래 예측을 읽는 순간에 과거 성적이 보이게.

### 1.4 우리 페이지의 성적 (자동 편입)

F1 changelog에 `type: achieved`(또는 예측 연도 경과)가 기록되면 해당 기술이 이 아카이브에
자동 편입된다. 시간이 지날수록 "이 사이트가 추적해온 예측의 성적" 섹션이 자라난다 —
페이지가 스스로 성적표를 쌓는 구조.

## 2. 데이터 모델 — `data/future/track_record.yaml`

```yaml
- id: comsat
  name: 통신위성
  predicted_by: 아서 클라크          # 주체 (스코어카드 집계 키: by_id 별도)
  by_id: clarke
  predicted_in: 1945                # 예측을 한 시점
  predicted_for: "1960년대"          # 예상 시점 (표시용 문자열)
  predicted_for_year: 1965          # 계산용 대표 연도
  actual_year: 1965                 # 실제 시점 (미완이면 null)
  actual_label: 인텔샛 1호 상업 서비스  # "완성"을 무엇으로 판정했는지 (3절)
  status: on_time                   # early | on_time(±2y) | late | missed | pending
  what: 지구 위 고정된 자리에 떠서 전 세계에 방송을 중계하는 인공위성입니다.
  outcome: 예측한 그 궤도에 20년 뒤 실제 위성이 올라갔습니다.
  lesson: 물리 법칙에서 출발한 예측은 시점까지 잘 맞는 편입니다.   # "왜" — 교육 페이로드
  source: "https://..."             # 예측 원문·판정 근거, 필수
```

- `status`는 빌드에서 `predicted_for_year`/`actual_year`로 자동 계산 (수기 입력과 불일치 시 경고).
- 스코어카드 통계(적중률·평균 오차)도 빌드에서 계산 — 수기 통계 금지.
- F1 changelog `achieved` 항목은 빌드 시 이 스키마로 자동 변환·병합 (`by_id`는 F1의 예측 출처).

## 3. 판정 규칙 — "완성"의 기준을 항목마다 명시

이 기능의 최대 함정: "화상통화는 1964년 Picturephone 출시가 완성인가, 2010년대 보편화가
완성인가?" 판정 기준이 흔들리면 성적표 전체가 자의적이 된다.

- 원칙: **예측자가 말한 것을 기준으로 판정한다.** "화상통화 기술"을 예측했으면 시연/출시가,
  "보편화"를 예측했으면 대중 보급이 기준. `actual_label`에 판정 근거를 반드시 쓴다.
- 부분 달성은 쪼갠다: "2009년까지 음성 비서 보편화 + 자율주행 상용화" 같은 묶음 예측은
  항목을 분리해 각각 판정.
- `on_time`은 ±2년. `missed`는 예상 시점에서 10년 이상 경과 + 실현 조짐 없음 (판정 보수적으로
  — 늦는 것과 안 오는 것은 다르다).
- 판정 불가(예측이 모호해 기준을 세울 수 없음)면 수록하지 않는다 — 흥미로워도 뺀다.

## 4. 초기 콘텐츠 후보 (⚠️ 전 항목 구현 시 문헌 검증 — 연도·출처 확인 필수)

| 예측 | 주체·시점 | 예상 → 실제 | 상태 후보 |
|---|---|---|---|
| 정지궤도 통신위성 | 아서 클라크, 1945 | 1960년대 → 1965 | on_time |
| 인간 게놈 해독 | HGP, 1990 | 2005 → 2003 | early |
| 화상통화 보편화 | AT&T Picturephone, 1964 | "10년 내" → 2010년대 | late |
| 핵융합 상업 발전 | 업계 낙관론, 1970년대 | ~2000 → 미완 | missed |
| 체스 세계챔피언 격파 AI | 카스파로프 대국 전 예측들 | → 1997 딥블루 | (주체별 상이) |
| 튜링 테스트 통과 | 튜링, 1950 | 2000 → (판정 논쟁 — 3절 기준으로 수록 여부 결정) ⚠️ | late/pending |
| 음성인식 실용화 | 커즈와일, 1999 (『영혼이 있는 기계의 시대』 2009 예측군) | 2009 → 2010년대 중반 | late |
| 완전자율주행 | 업계 다수, 2015~16 | 2020 → 부분(2020년대 로보택시) | late |
| 태양광 발전 단가 | IEA 전망 vs 실제 | 반복적 과소예측 → 실제가 더 빨랐음 | early |
| 상업 우주 관광 | 2000년대 초 업계 | 2010년경 → 2021 | late |
| 유전자 치료 보편화 | 1990년대 학계 | 2000년대 → 2010년대 후반 첫 승인들 | late |
| 종이 없는 사무실 | 1975 비즈니스위크 등 | 1990 → 사실상 2010년대 | late |

12건 내외로 시작 (스코어카드가 의미를 갖는 최소량). 커즈와일 항목을 2~3건 확보해
F1 출처 배지(1.3절)가 실데이터로 작동하게 한다. 콘텐츠 작성은 수동 큐레이션 —
역사적 사실의 정확성이 생명이므로 **F5 에이전트 자동 게재 범위에서 제외**한다
(다독 방침은 읽을거리에 적용되는 것이지, 사실 데이터에는 적용되지 않는다).

## 5. 작성 기준 (톤)

- F1 5절 승계: `what`/`outcome`/`lesson` 각 1~2문장, 첫 문장 전문용어 0, 과장 금지.
- **조롱 금지**: "황당한 예측" 어조 대신 "왜 그렇게 봤는지"를 담는다. 당시엔 합리적이었던
  이유가 있으면 그것이 `lesson`이다.
- `lesson`은 일반화 가능한 교훈 한 줄로: "물리 기반 예측은 시점이 잘 맞는다",
  "기술 완성과 대중 보급 사이엔 보통 10년이 있다", "업계의 자기 제품 예측은 낙관적이다".
  이 문장들이 모여 독자의 예측 리터러시가 된다.

## 7. AC

- 성적표 뷰에서 12건 내외의 예측이 예상→실제 덤벨로 보이고, 상태가 색으로 구분된다.
- 행을 펼치면 무엇을 예측했고 실제로 어떻게 됐고 왜 그랬는지가 3문으로 보이고, 예측 원문 출처 링크가 있다.
- 모든 항목에 `actual_label`(판정 기준)이 표시된다 — "무엇으로 완성을 판정했나"를 독자가 확인 가능.
- 주체 스코어카드의 적중률·평균 오차가 YAML이 아닌 빌드 계산값이다.
- F1 기술 카드에서 커즈와일 예측 옆에 과거 성적 배지가 보이고, 클릭 시 성적표 뷰의 해당 주체 필터로 이동한다.
- F1 changelog에 `achieved`가 추가되면 다음 빌드에서 성적표에 자동 등장한다.
- 판정 기준·연도가 확인 안 되는 항목은 수록되지 않았음이 PR 설명에 정리되어 있다.

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| 판정의 자의성 ("완성"이 언제냐) | 3절 규칙: 예측자의 문언 기준 + `actual_label` 필수 노출 + 모호하면 미수록 |
| 역사적 사실 오류 | 수동 큐레이션 + 출처 필수 + F5 자동 게재 제외 |
| 조롱 콘텐츠화 (밈化) | 5절 톤 기준 + `lesson` 필드 필수 — "왜"가 없는 항목은 반려 |
| 생존 편향 (유명한 예측만 수록 → 성적 왜곡) | 스코어카드에 "수록 기준: 문헌 확인 가능한 예측" 고지 + 적중·빗나감 균형 있게 수록 |
| 주체 통계의 표본 부족 (n=2로 "적중률 50%") | 판정 완료 5건 미만 주체는 배지·통계 미노출 (건수만 표시) |
