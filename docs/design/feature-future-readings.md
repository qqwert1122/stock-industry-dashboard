# 기능 설계 — '미래' 읽을거리 레이어 (F4) [Tier 3]

상태: 기획 초안 (2026-07-10). 목적: '미래' 페이지의 각 기술에 **읽을만한 리포트·뉴스레터를
학습 경로로 연결**한다. 대시보드가 "여기까지 왔다"를 보여준다면, 이 레이어는 "더 알고 싶으면
이걸, 이 순서로"를 안내한다. 수치·지표는 기존 수집 범위이므로 이 문서 범위 밖.

의존성: F1(feature-future-timeline.md) 머지 후 — 기술 상세 화면에 섹션을 추가하는 구조.
F2/F3과는 독립적으로 진행 가능.

공통 제약: **운영 비용 0원**. 링크 대상도 무료 열람 가능한 자료만 (구독형 뉴스레터는 무료 티어 기준).

---

## 0. 사용자 교육 관점 — 링크 모음이 아니라 학습 경로

실패 패턴부터 정의한다: **링크 덤프는 아무도 누르지 않는다.** "참고 자료 12개" 목록은
운영자의 북마크이지 사용자 교육이 아니다. 일반인 독자에게 필요한 건 세 가지다:

1. **뭘 먼저 봐야 하나** — 순서가 있는 경로 (입문 → 중급 → 심화)
2. **누르기 전에 뭘 얻을지** — 모든 링크에 "이걸 보면 ~를 알게 됩니다" 한 줄
3. **부담의 사전 고지** — 언어(한/영), 분량(10분/보고서), 발행 주기(연 1회/주간)

설계 원칙:

- **적당한 것 여러 개 > 완벽한 것 하나.** (운영 방침 확정, 2026-07) 초보 학습자에게는
  엄선된 양서 하나보다 무난한 자료 여러 개를 훑는 다독이 낫고, 콘텐츠가 빈 것이 최악이다.
  상한은 레벨당 8개 — 편집 기준이 아니라 덤프 방지용 가드일 뿐이다.
- **선별은 배지와 정렬로 대신한다**: 양을 늘리는 대신 `검증된 발행처`(trusted_domains) 배지를
  달고 그 항목을 먼저 정렬한다. 무엇을 뺄지 고르는 대신, 좋은 것이 먼저 보이게 한다.
- **레벨 필수**: 입문(전문지식 0, 가능하면 한국어/영상) · 중급(연례 리포트 — 이 분야의 "교과서") ·
  심화(원자료·데이터). 입문이 비어 있으면 빌드 경고 — 반려가 아니라 "채워야 한다"는 신호로,
  F5 에이전트의 갭 목록에 잡힌다.
- **살아있는 소스 우선**: 일회성 아티클보다 매년 갱신되는 리포트, 계속 발행되는 뉴스레터.
  이 페이지의 정체성이 "지속 관찰"이므로 읽을거리도 관찰 도구여야 한다.
- **F1 톤 가이드 준수**: 추천 이유도 5절 규칙(전문용어·과장 금지)을 따른다.

## 1. UI

### 1.1 기술 상세 — "더 깊이 알아보기" 섹션

F1 기술 상세의 마지막 섹션(관련 기업 다음)에 배치. 서사의 종점이 "직접 공부"가 되도록.

- **레벨 3단 구성**: 입문은 기본 펼침, 중급·심화는 접기(아코디언). 모바일 동일.
- 행 구성: 유형 아이콘(📄 리포트 / ✉️ 뉴스레터 / 📚 책 / ▶ 영상) · 제목 · 메타 칩
  (`한국어`/`영어` · `10분`/`보고서` · `매년 4월`/`주간`) · 추천 이유 1줄 · 외부 링크 아이콘.
- 뉴스레터는 "구독형" 배지 — 클릭이 구독 페이지로 간다는 걸 사전 고지.
- 신뢰 신호 배지: `검증된 발행처`(trusted_domains 도메인) 표시, 해당 항목을 레벨 내 상단 정렬.
  에이전트(F5)가 추가한 항목은 `자동 수집` 라벨 — 독자에게 큐레이션 방식을 정직하게 고지.
- 외부 링크 정책: `target="_blank"` + `rel="noopener noreferrer"`, 섹션 하단에 한 줄 고지
  "외부 자료는 각 발행처의 관점을 담고 있으며, 본 사이트와 무관합니다."

### 1.2 타임라인 하단 — "미래를 읽는 법" 공통 섹션

특정 기술에 속하지 않는 횡단 자료(기술 확산 곡선, TRL 개념, 커즈와일 원저)를 타임라인
맨 아래에 고정 배치. 페이지 전체의 "0교시" 역할. 항목 수 ≤4.

### 1.3 glossary 툴팁 연결 (선택)

F1 glossary 항목에 `learn_more` URL 1개를 선택 필드로 허용 — 툴팁 하단 "자세히" 링크.
용어당 1개 초과 금지.

## 2. 데이터 모델 — `data/future/readings.yaml`

F1과 동일한 콘텐츠=코드 원칙: `why`(추천 이유)와 `checked_at`(링크 확인일) 필수.

```yaml
- tech: agi                      # technologies.yaml의 id. 공통 자료는 tech: _common
  items:
    - title: Stanford AI Index Report
      url: "https://hai.stanford.edu/ai-index"        # ⚠️ 구현 시 검증
      type: report               # report | newsletter | book | video | explainer
      level: 중급                 # 입문 | 중급 | 심화
      lang: en
      effort: 보고서              # 10분 | 30분 | 보고서 | 책
      cadence: 매년 4월           # 발행 주기 (일회성 자료는 생략)
      why: 한 해의 AI 진행 상황을 숫자로 총정리한, 이 분야의 공식 성적표입니다.
      checked_at: 2026-07-10
      curated_by: human           # human | agent — agent면 UI에 '자동 수집' 라벨
```

빌드: `future.json`에 `readings` 병합. 필수 필드 누락·입문 0개는 fetch_log 경고,
레벨당 8개 초과는 차단(초과분 미게재 + 경고).

## 3. 초기 콘텐츠 후보

리포트는 랜딩 페이지를 링크). 한국어 입문 자료는 콘텐츠 작성 시 조사해 기술당 1개 이상 확보를

## 4. 콘텐츠 선정·작성 기준 (교육 관점 체크리스트)

리뷰 시 이 기준으로 반려한다:

1. **무료 열람** 가능한가 (페이월 뒤 자료 금지, 뉴스레터는 무료 티어 기준).
2. **발행 주체 확인** — 기관·학계·전업 저자면 `검증된 발행처` 배지. 개인 블로그·유튜브도
   허용한다(다독 방침 — 배지 없이 게재). 단 blocked_domains(리딩방·콘텐츠팜·스팸·SNS 포스트)는
   품질과 무관하게 금지.
3. **투자 권유 성격이 없는가** — 증권사 리포트·종목 추천 콘텐츠 금지 (ARK Big Ideas처럼
   운용사 발행물은 "낙관 편향이 있는 전망"임을 `why`에 명시하는 조건으로 허용).
   **이 기준만은 다독 방침과 무관하게 타협 불가** — 미래 페이지가 리딩방 입구가 되는 순간 끝이다.
4. `why`는 "이걸 보면 ~를 알게 됩니다" 형식, 40자 내외, 전문용어 0.
5. 입문 자료는 **전문지식 없이 10분 안에** 소화 가능한 것만.
6. 링크는 개별 PDF가 아니라 **랜딩 페이지** — 연도 갱신 시 링크가 살아남게.

## 5. 링크 건강 관리 (link rot)

교육 레이어의 신뢰는 링크가 살아있는 데서 나온다:

- 풀빌드에서 주 1회(요일 조건) readings URL 전체를 HEAD/GET 체크 — `ThrottledSession` 경유,
  실패 시 fetch_log 경고만 (UI 노출·빌드 실패 없음. 일시 장애 오탐 방지를 위해 2회 연속 실패부터 경고).
- `checked_at`이 180일 초과 시 스테일 경고 — F1의 `as_of` 규칙과 동일 문법.
- 연례 리포트 발행 시즌(AI Index 4월, FIA 여름, IFR 가을, State of AI 10월, ARK 1월, DMV 2월)을
  `data/calendar`에 `future` 카테고리로 등록 → E1 캘린더가 운영자에게 갱신 숙제를 상기.
  이 발행 일정은 사용자에게도 노출 가치가 있다 (선택: 읽을거리 행에 "다음 호: 2027-04").

## 7. AC

- 기술 상세에서 입문 자료가 펼쳐진 상태로 보이고, 각 항목에 추천 이유·언어·분량·발행 주기가 표시된다.
- 모든 기술에 입문 레벨 자료가 1개 이상 있다 (없으면 빌드 경고).
- 외부 링크는 새 탭으로 열리고 섹션에 외부 자료 고지가 있다.
- 죽은 링크가 2회 연속 감지되면 /admin(fetch_log)에 경고가 남고, 사용자 화면에는 영향이 없다.
- 뉴스레터 항목에 구독형 배지가 보인다.
- `검증된 발행처` 배지 항목이 레벨 내 상단에 정렬되고, `curated_by: agent` 항목에 `자동 수집` 라벨이 보인다.
- 타임라인 하단에 공통 읽을거리 섹션이 있다.
