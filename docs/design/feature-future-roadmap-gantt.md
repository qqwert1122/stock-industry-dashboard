# 기능 설계 + 콘텐츠 — 기술별 로드맵 간트 차트 (F9) [Tier 2]

상태: 기획 + 콘텐츠 초안 (2026-07-11). 목적: 각 미래 기술의 진행을 **간트 차트**로 보여준다 —
단계(요소 기술·마일스톤)가 가로 막대로 시간 축에 놓이고, "오늘" 세로선이 지나가며,
완료·진행·추정 구간이 색으로 구분된다. 타임라인(F1)이 "기술들이 언제 오나"의 조감도라면,
간트는 **한 기술 안에서 무엇이 언제 일어나는가**의 공정표다.

**객관성에 대한 방침 (운영자 확정)**: 미래 구간은 어차피 추정이다. 완벽한 객관성 대신
① 모든 추정 막대에 "추정" 표시와 근거 한 줄 ② 연 1회 재추정 ③ **재추정 이력 보관·표시**
(밀리면 밀린 대로 보이게)로 정직성을 확보한다. 예보가 아니라 "지도 초안"이며, 지도가
틀렸음이 드러나는 과정 자체가 콘텐츠다(F6 성적표의 실시간 버전).

의존성: F1·F2·F7 머지 후. F8 콘텐츠가 있으면 함께 수록(없어도 F1 기술만으로 동작).
지식 기준일 2026-01 — 4절 시드의 연도는 저자 추정.

공통 제약: **운영 비용 0원.** 정적 YAML + SVG 자체 렌더(라이브러리 없음).

## 0. 화면이 답해야 할 질문

1. **이 기술은 지금 공정의 어디쯤인가** — 오늘 선이 어느 막대들을 지나는가
2. **다음에 올 일은 무엇인가** — 오늘 선 오른쪽의 첫 막대·마름모(마일스톤)
3. **일정이 밀리고 있는가** — 이전 추정 대비 밀림/당김 표시
4. **예측자들은 언제라고 했나** — F1 예측 연도를 마름모 마커로 같은 축에 병기
   (우리 추정 로드맵과 외부 예측을 한 화면에서 비교)

## 1. UI

### 1.1 간트 뷰 (기술 상세 내 섹션, F2 순서도와 F7 사다리 사이)

```
로보택시                        2018      2022      오늘      2030      2034
  L4 기술 실증                  ████████████░
  도시 확장 (미국)                        ██████████│██████▒▒
  규제·보험 프레임                            ██████│████▒▒▒▒
  전용 차량·원가                                ████│███▒▒▒▒
  대중화                                         │      ▒▒▒▒▒▒▒▒
                                                오늘│    ◆2027 커즈와일
```

- 가로축 = 연도(과거 ~8년 + 미래 ~10년, 기술별 자동 산정). **오늘 세로선**이 기준.
- 막대 상태 3색: `done`(회색+체크) · `active`(진행, 채움) · `projected`(추정 — 점선 테두리
  +옅은 채움, 시작·끝이 흐릿한 페이드로 "확정 아님"을 시각 언어로).
- **마름모 마커** = 이벤트: F1 예측 연도(커즈와일·로드맵), 실제 달성 이벤트(changelog),
  주요 마일스톤(형식인증 취득 등).
- **밀림 표시**: 재추정으로 막대가 이동하면 이전 위치를 유령 막대(외곽선만)로 남기고
  "→ 2년 밀림" 배지. 당겨지면 반대로. 이력은 최근 1회분만 표시(전체는 상세에서).
- 막대/마름모 클릭 → 상세 패널: 이 단계에서 무슨 일이 일어나는지(desc) · 왜 이 기간으로
  추정했는지(basis) · 연결된 F7 사다리 단·지표 링크 · 재추정 이력 전체.
- 상단 고지(모든 간트 공통): "미래 구간은 운영자의 추정입니다. 근거와 수정 이력을
  함께 보세요." — 주관성의 정직한 고지.

### 1.2 모바일

가로 스크롤 금지 원칙 유지 → 모바일은 연도 축을 압축(오늘 ±6년 기본, 좌우 접기 버튼으로
과거/먼 미래 확장). 막대 라벨은 막대 위 줄바꿈 배치.

### 1.3 전체 조감 간트 (선택, 후순위)

타임라인 하단에 "모든 기술 × 대표 단계 1줄"의 압축 간트 1장 — 기술 간 속도 비교용.
기술이 15개라 행이 많아지므로 분야 필터 연동. F9 범위에서는 선택 구현.

## 2. 데이터 모델 — `data/future/roadmap.yaml`

```yaml
- tech: robotaxi
  phases:
    - id: rt-l4-proof
      name: L4 기술 실증
      start: 2018
      end: 2023
      status: done                    # done | active | projected
      desc: 무인 차량이 실제 도로에서 사람 없이 유상 운행할 수 있음을 증명한 구간.
      basis: Waymo 무인 상용 개시(2020)~확대. 종료는 상용 확장 개시 기준.
      links: { ladder_rung: [sae-autonomy, L4], metrics: [waymo-rides] }
      confidence: high
    - id: rt-mass
      name: 대중화
      start: 2028
      end: 2032
      status: projected
      desc: 주요 도시에서 로보택시가 일상 교통수단이 되는 구간.
      basis: 도시 확장 속도와 규제 진행을 잇는 저자 추정. 규제 지연 시 밀림.
      confidence: low
      revisions:                      # 재추정 이력 — 밀림/당김의 기록
        - { date: 2026-07, start: 2028, end: 2032, note: 최초 추정 }
  markers:
    - { year: 2027, type: prediction, label: 커즈와일 예측, ref: f1 }
```

- `status`는 빌드가 오늘 날짜로 검증(끝난 active, 시작 전 done 등 모순 경고).
- `revisions`는 append-only — 수정 시 이전 항목을 지우지 않는다. **이 파일이 곧
  "우리 추정의 성적표"가 된다** (F6 자동 편입 후보).
- changelog(F3)의 achieved/milestone 이벤트는 마커로 자동 병합.
- 연도 단위(반기 표현은 0.5)로 단순화 — 월 단위 정밀도는 거짓 정확성.

## 3. 작성·갱신 기준

- 단계 수 4~6개/기술. 7개 이상이면 합쳐라 — 간트는 공정표이지 작업 분해도가 아니다.
- 모든 `projected` 막대에 `basis` 필수 (근거 없는 막대는 빌드 경고). basis는 한 줄:
  무엇을 근거로 잇거나 늘렸는지.
- `desc`는 일반인 문장 (F1 톤 가이드: 첫 문장 전문용어 0).
- 재추정은 연 1회(반기 TRL 리뷰와 동시) + 큰 이벤트 시 수시. 수정은 반드시 `revisions`에.
- `nature: governance`(지구공학)는 간트 제외 — 시간 축 자체가 부적절 (F8 원칙 승계).
- 사실 데이터+저자 추정 혼합물이므로 **F5 자동 게재 제외**.

  실증 발전(전력망 연결) 2030–2036 projected → 상업 발전 2035–2042 projected.

- **우주 상업화**: 재사용 로켓 done → 초대형 로켓 정례화 2024–2028 active →
  $/kg 추가 하락 2028–2033 projected → 궤도·달 인프라 2030– projected.
- **유전자 치료**: 개별 승인 시대 2017–2028 active → 비용 하락·적응증 확대 2026–2032
  projected → 보편화 2032– projected. basis: 승인 건수 추이와 치료비 곡선.
