# 기능 설계 — 시그널 이력 (H1): 임계 돌파 타임라인

상태: 확정 (2026-07-09). 목적: 임계값 룰(config.yaml `alerts:`)의 발동/해제 이벤트를 **텔레그램
발송 여부와 무관하게** 이력으로 축적하고, 사이트에서 타임라인과 차트 마커로 보여준다.

배경: 알림 룰 평가 인프라(alerts.py)는 이미 존재하고 매 빌드 실행되지만, 상태 파일
(data/alerts_state.json)은 "마지막 상태"만 저장해 **과거 이력이 없다**.
**이력의 기준은 "트리거 발동/해제"이지 "텔레그램 실제 발송"이 아니다** — 텔레그램은 선택적 발송
채널일 뿐이며(시크릿 없으면 미발송), 시크릿이 없어도 이력은 동일하게 쌓인다.
(디버깅용으로 이벤트에 `telegram_sent: bool` 필드만 기록하되 피드에는 표시하지 않는다.)

의존성: 백엔드(로그 축적·백필)는 즉시 가능. 프론트(우측 Drawer)는 특정 메뉴 구조에 의존하지
않지만 같은 템플릿 파일이므로 순차 진행 — 프론트 순서: B1 → S1 → C1 → **H1 프론트** → A4
(순차라면 H1 위치는 유연).

## 1. 데이터 모델 — `signal_log`

### 1-1. 이벤트 기록 (alerts.py 확장)

`process_alerts()`에서 룰 상태가 **전이될 때만** 이벤트를 append:

```json
// data/signal_log.json (전체 보존, 워크플로 복원/커밋 대상) → site/data/signal_log.json 복사
{ "version": 1,
  "events": [
    { "ts": "2026-07-02T08:04:00+09:00",      // 전이를 감지한 빌드 시각
      "observed_at": "2026-07-02",             // 지표 데이터 기준일
      "rule_key": "원/달러 환율|above=1500",
      "metric_id": "a1b2c3d4",                 // name 조각 매칭 결과의 id를 고정 기록
      "metric_name": "원/달러 환율",
      "direction": "triggered",                // triggered | cleared
      "value": 1538.05, "display_value": "1,538원",
      "threshold_label": "≥ 1500",
      "message": "환율이 위기 수준입니다. …",   // 룰의 message
      "context": {                              // 발동 시점의 시장 맥락 (그때 코스피가 어디였나)
        "KS11": 3125.4, "GSPC": 6350.1, "USDKRW": 1538.05 }
    } ] }
```

- `cleared`(해제) 이벤트도 기록 — "언제부터 언제까지 발동 상태였나"를 구간으로 재구성 가능.
- context 지표 셋은 고정 3종(코스피, S&P500, 원/달러)으로 시작. 페이로드에서 조회.

### 1-2. 과거 이력 소급 백필 (일회성, 큰 부가가치)

이력 축적을 오늘부터 시작하면 페이지가 수년간 빈약하다. **data/history/의 장기 시계열에 룰을
소급 적용해 과거 발동/해제 이벤트를 재구성**한다:
- `above`/`below` 룰(값 임계): 해당 지표 히스토리 전 구간에서 교차 지점을 정확히 계산 가능.
  VIX>40이면 2020-03, 2024-08 등이 나온다. context의 코스피/S&P500도 각 시점 히스토리에서 조회.
- `pct_above`/`pct_below` 룰(퍼센타일 임계): 시점별 롤링 퍼센타일 재계산이 필요해 비용이 큼 →
  **백필 제외**하고 이벤트에 `backfilled: true` 플래그가 없는 실측만 사용. 페이지에
  "퍼센타일 룰은 (백필 시작일)부터 집계" 캡션.
- 백필 이벤트에는 `backfilled: true` 표시 (빌드 시각이 아닌 데이터 기준일만 신뢰 가능).
- 구현: 일회성 스크립트가 아니라 `signal_log.json`이 비어 있을 때 1회 자동 실행되는 초기화 루틴
  (재현 가능, 로컬 테스트 용이).

## 2. UI — 우측 Drawer 알림 피드 (메뉴 페이지 아님)

좌측 Drawer(메뉴)와 대칭 구조: **히스토리 플로팅 버튼 → 우측에서 Drawer가 열리며 알림 피드 표시.**

### 히스토리 플로팅 버튼
- 위치: 화면 우측 (좌측 메뉴 토글 버튼과 대칭, PC·모바일 공통). 아이콘: 종(🔔) 계열,
  기존 `.mobile-menu-toggle` 버튼 스타일·CSS 변수 재사용.
- **미확인 뱃지**: 마지막으로 Drawer를 연 시각을 localStorage에 저장하고, 그 이후 새 이벤트가
  있으면 버튼에 점(dot) 표시. Drawer를 열면 해제.

### 우측 Drawer
- PC: 우측 고정 폭 ~380px 패널, 모바일: 화면 폭 ~85% (좌측 Drawer와 동일한 오버레이·딤 패턴 재사용).
- 닫기: X 버튼, ESC, 딤 영역 클릭.
- 내부 구성 (위→아래):
  1. **"지금 발동 중" 고정 섹션** — 현재 triggered 상태인 룰 카드 (alerts_state 기준, 경고색 테두리)
  2. **필터 칩 (가로 스크롤)** — 전체 / 발동만 / 룰별(VIX, PBR, 환율, …)
  3. **이벤트 피드 (최신순)** — 알림 카드 형식: 방향 배지(**발동**=경고색 / **해제**=중립색) ·
     지표명 · 당시 값과 임계(`1,538원 ≥ 1500`) · 룰 message · 당시 코스피/S&P500 (context) · 날짜.
     발동~해제 짝에는 발동 카드에 "지속 N일" 라벨. 백필 이벤트는 옅은 스타일 + "소급" 뱃지.
- 피드는 50건 단위 렌더 + "더 보기" (signal_log가 커져도 DOM 부담 없게).
- 카드의 지표명 클릭 → Drawer 닫고 해당 지표 디테일로 이동.

### 차트 마커 (시너지)
- 지표 디테일 상세 차트에서, 그 지표에 걸린 룰의 발동 이벤트 시점에 세로 마커(▲) 표시.
  호버 시 이벤트 요약 툴팁. C1 비교 모드에서도 기준 지표의 마커는 유지.
- 예: 코스피 차트를 열고 VIX>40 마커를 볼 수는 없음(다른 지표의 룰) — v1에서는 **자기 지표
  룰만** 마커로. "코스피 위에 전체 시그널 마커" 오버레이는 C1 사용 패턴을 보고 후속 검토.

## 4. AC
- 빌드에서 룰이 새로 발동/해제되면 signal_log에 이벤트가 1건씩만 추가된다 (중복 없음).
  텔레그램 시크릿 유무는 기록에 영향을 주지 않는다.
- 우측 플로팅 버튼 → Drawer가 열리고, 과거 VIX>40 발동 이력(소급 포함)이 당시 코스피 값과 함께
  피드로 보인다. 새 이벤트 발생 시 버튼에 미확인 dot이 떴다가 열람 후 사라진다.
- 현재 발동 중인 룰(예: CAPE 95분위, 환율>1500)이 Drawer 최상단 고정 섹션에 표시된다.
- 피드 카드의 지표명 클릭 시 Drawer가 닫히고 해당 지표 디테일로 이동한다.
- VIX 지표 디테일 차트에 과거 발동 시점 마커가 찍히고 호버 시 상세가 뜬다.
- PC/모바일 폭·다크모드에서 Drawer가 정상 동작하고, 좌측 메뉴 Drawer와 동시 열림이 없다.
