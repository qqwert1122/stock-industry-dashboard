# 기능 설계 + 위키 — 기술 요구사항 브레이크다운 (F7) [Tier 2]

상태: 기획 + 콘텐츠 초안 (2026-07-10). 목적: 각 미래 기술을 실현하기 위해 **어떤 요소
기술이, 어느 수준까지 도달해야 하고, 지금은 어느 단계이며, 누가 그 수준을 달성했는지**를
도메인별 실제 기술 사다리로 세분화해 보여준다. F2의 일반 TRL(1~9)이 "얼마나 성숙했나"의
추상 척도라면, F7은 "자율주행 L1~L5 중 몇 단계", "4G→5G→6G 중 어디", "HBM 몇 세대"처럼
**분야 고유의 구체적 단계**로 내려간다.

이 문서는 기획(1~3절)과 **위키 콘텐츠 본문(4절)**을 함께 담는다. 4절은 웹서핑이 아니라
저자 지식으로 작성한 초안이며, 개발 시 `data/future/breakdown.yaml`의 시드 콘텐츠가 된다.

의존성: F1·F2 머지 후 (F2의 component 개념을 확장). 지식 기준일 2026-01 — 이후 변동은
changelog(F3)로 갱신.

공통 제약: **운영 비용 0원.** 콘텐츠는 정적 YAML, 수치는 기존 수집 지표 참조.

> ⚠️ 정확성 주의: 4절 수치·기업·단계는 2026-01 지식 기준의 저자 작성분이다. 개발 편입 전
> 각 항목의 `as_of`를 확인하고, 빠르게 변하는 값(HBM 세대, 자율주행 상용 도시 등)은
> 반드시 최신 확인 후 수록한다. 근거가 흔들리는 항목엔 `confidence: low` 표시.

## 0. 왜 이 세분화가 필요한가 (교육 관점)

일반인이 "로보택시가 언제 되나"를 이해하려면 "자율주행이 어렵다"로는 부족하다.
"L4까지 가야 하는데 지금 특정 도시에서만 L4고, 일반 판매차는 L2에 머물러 있으며,
진짜 벽은 기술이 아니라 도시를 넓히는 것"이라는 그림이 있어야 "언제"가 감이 온다.

F7이 F2와 다른 점:
- **F2**: component마다 TRL 1~9 하나. "규제·보험 TRL 4" — 성숙도만.
- **F7**: component마다 **분야 고유 사다리 + 목표 단(rung) + 현재 단 + 달성 기업 + 임계 수치**.
  "자율주행: [L0…L5] 사다리, 목표 L4, 현재 L4(지역 한정)/L2(양산차), 달성 Waymo,
  판정 지표 = 개입 없는 주행거리."

교육 페이로드는 **"목표 단과 현재 단의 간격"**이다. 그 간격이 곧 "얼마나 남았나"이고,
간격이 가장 큰 요소가 곧 병목이다.

## 1. 데이터 모델 — `data/future/breakdown.yaml`

F2 component에 "능력 사다리(capability ladder)"를 붙인다. 사다리는 재사용 가능한
독립 엔티티(여러 기술이 같은 사다리를 참조: 자율주행 사다리는 로보택시·자율트럭이 공유).

```yaml
# ladders.yaml — 재사용 가능한 능력 사다리
- id: sae-autonomy
  name: 자율주행 자동화 단계 (SAE J3016)
  rungs:                                  # 낮은→높은 순
    - { level: L0, label: 비자동, desc: 운전자가 전부 조작 }
    - { level: L1, label: 운전자 보조, desc: 조향 또는 가감속 하나를 보조 (크루즈컨트롤) }
    - { level: L2, label: 부분 자동, desc: 조향+가감속 동시 보조, 운전자 상시 감독 }
    - { level: L3, label: 조건부 자동, desc: 특정 조건서 차가 운전, 요청 시 운전자 개입 }
    - { level: L4, label: 고도 자동, desc: 특정 구역(ODD) 내 완전 무인, 개입 불필요 }
    - { level: L5, label: 완전 자동, desc: 모든 도로·조건서 무인 }
  source: "https://www.sae.org/standards/content/j3016_202104/"

# breakdown.yaml — 기술별 요구 요소 (F2 component를 확장)
- tech: robotaxi
  requirements:
    - id: rt-autonomy
      name: 자율주행 소프트웨어
      ladder: sae-autonomy
      required_rung: L4                    # 이 기술 실현에 필요한 단
      current_rung: L4                     # 현재 최고 도달 단
      current_note: 지역 한정 L4 상용 / 일반 판매차는 L2
      achieved_by: [Waymo]                 # 목표 단 달성 주체
      pursuing: [Tesla, Baidu, Zoox, Mobileye]
      metric: 개입 없는 평균 주행거리 (miles per intervention)
      metric_ref: waymo-rides              # 기존 수집 지표 키(있으면)
      gap: 기술은 L4 도달. 벽은 ODD(운행 구역)를 도시 단위로 넓히는 속도와 비용.
      what: 사람이 운전대를 안 잡아도 차가 스스로 판단해 달리는 소프트웨어입니다.
      confidence: high
      as_of: 2026-01
      source: "https://..."
```

- `required_rung`과 `current_rung`을 사다리에서 찾아 **간격(gap rungs)을 빌드가 계산**,
  UI 진행 바에 반영. 간격 최대 요소 = 자동 병목 후보 (F2 bottleneck과 교차 검증).
- `achieved_by`/`pursuing`은 F1 기업 칩과 동일 티커 체계 참조.
- 사다리가 없는(연속량) 요소는 `ladder: null` + `metric`의 임계값 표기
  (예: 발사 비용 "$/kg, 목표 <$1000, 현재 ~$1500").

## 2. UI

### 2.1 기술 상세 — "무엇이 필요한가" 섹션 (F2 TRL 스택 자리 확장)

각 요소를 **사다리 진행 바** 행으로:

```
자율주행 소프트웨어           목표 L4 · 현재 L4(지역한정)
  L0 ─ L1 ─ L2 ─ [L3] ─ ●L4 ─ L5     달성: Waymo   추적: Tesla·Baidu…
  └ 개입 없는 주행거리 ↗   벽: 기술 아닌 도시 확장 속도

이동통신                     목표 5G · 현재 5G 상용
  3G ─ 4G ─ ●5G ─ (5G-A) ─ (6G)      달성: 통신 3사·통신칩 QCOM
  └ 안전 필수 기능은 통신 없이도 동작해야 (보조 역할)

차량 원가                    목표 <$3만 · 현재 추정 $5만~
  ├────────●───┤ (연속량 바)          추적: Tesla·현대·Zoox
```

- 사다리형: 단(rung) 칩을 낮은→높은 순 나열, 목표 단은 테두리 강조, 현재 단은 채움 점(●),
  둘 사이 구간을 색으로 (도달=teal, 남은 구간=회색). 목표<현재면 "충족" 배지.
- 연속량형: 임계선이 표시된 단일 진행 바.
- 각 행 하단: 판정 지표(클릭 시 기존 지표 차트로) + 달성/추적 기업 칩 + `gap` 한 줄.
- **병목 행 강조**: 간격이 가장 큰 요소를 경고색 — F2 순서도의 병목과 일치해야 한다.

### 2.2 사다리 툴팁

단(rung) 칩 탭 시 해당 단의 `desc` 풀이 (L3 = "차가 운전하되 요청 시 사람이 넘겨받아야
하는 단계"). 사다리 정의는 재사용되므로 툴팁도 한 번만 작성.

### 2.3 F2 순서도와의 관계

F2 의존 순서도가 "요소 간 선후 관계(구조)"라면, F7은 "각 요소의 도달 수준(깊이)"이다.
순서도 노드 클릭 → F7 사다리 행으로 스크롤. 두 뷰는 같은 component를 다른 축으로 본다.

## 3. 콘텐츠 작성 기준

- 사다리는 **공인 표준 우선** (SAE J3016, 3GPP 릴리스, TRL). 표준이 없으면 업계 통용 세대
  구분을 쓰되 `source`에 근거. 임의 사다리 창작 금지.
- `required_rung`은 "이게 안 되면 그 미래가 성립하지 않는" 최소선. 있으면 좋은 수준(L5 등)이
  아니라 필요조건.
- `gap` 문장이 교육의 핵심: 기술적 벽인지, 비용인지, 규제인지, 확산 속도인지를 명시.
  "기술은 됐고 벽은 딴 데 있다"가 로보택시의 교훈처럼 자주 나온다.
- 기업 귀속은 검증 가능한 것만. "달성"과 "추진 중"을 구분 (`achieved_by` vs `pursuing`).
- 사실 데이터이므로 **F5 에이전트 자동 게재 제외** (F6과 동일 — 수동 큐레이션).

## 4. 위키 콘텐츠 (저자 작성 시드 — 지식 기준 2026-01)

> 개발 시 이 절을 `breakdown.yaml`로 옮긴다. 각 요소는 사다리 / 목표 / 현재 / 달성·추진 기업 /
> 판정 지표 / 간격(벽)으로 구성. 수치는 근사이며 `confidence`와 `as_of`를 함께 옮길 것.

### 4.1 로보택시 (robotaxi)

로보택시가 성립하려면 다섯 가지가 동시에 필요하다: 스스로 판단하는 자율주행, 세상을 보는
센서, 그걸 처리하는 차량용 컴퓨터, 낮은 차량 원가, 그리고 이를 도로에 허용하는 제도.
**기술 자체는 이미 상당수 도달했고, 진짜 벽은 "도시를 넓히는 속도"와 "제도"다.**

| 요소 | 사다리·임계 | 목표 | 현재 | 달성 | 추진 | 벽(gap) |
|---|---|---|---|---|---|---|
| 자율주행 SW | SAE L0~L5 | L4 | L4(지역 한정), 양산차 L2 | Waymo | Tesla·Baidu(Apollo Go)·Zoox·Mobileye | 기술 아닌 ODD(운행구역) 확장 속도·비용 |
| 센서 스위트 | 라이다·레이더·카메라 융합 성숙도 | 융합 상용 | 상용, 라이다 단가 급락 중 | Waymo·Mobileye | Luminar·Hesai 등 라이다 | Tesla는 카메라-only 노선 — 접근법 논쟁 미해결 |
| 차량용 컴퓨터 | 온보드 추론 성능(TOPS) | 실시간 L4 추론 | 충족(수백 TOPS급) | NVIDIA(DRIVE)·Tesla(FSD칩)·Mobileye(EyeQ) | Qualcomm | 성능보다 전력·발열·비용 최적화 단계 |
| 이동통신·관제 | 3G~4G~5G~6G | 5G(보조) | 5G 상용 | 통신3사·Qualcomm | — | 안전 필수 기능은 통신 없이 동작해야 — 통신은 원격관제·업데이트 보조 |
| 차량 원가 | $/대 (연속량) | <$3만(추정) | ~$5만+ 추정 | — | Tesla·현대·Zoox | 전용 양산 규모의 경제 도달 전 |
| 규제·보험 | 무인운행 허용 범위 | 도시 광역 허용 | 미국 일부 州·도시 부분 허용 | — | 각국 규제당국 | **최대 병목** — 사고 책임·보험 프레임 미비 |

핵심 사다리 설명 — 자율주행 SAE 6단계:
- L0 비자동 → L1 보조(크루즈컨트롤) → L2 부분자동(조향+속도 동시 보조, 운전자 상시 감독,
  현재 대부분의 "자율주행" 판매 기능이 여기) → L3 조건부(차가 운전하되 요청 시 인계,
  Mercedes Drive Pilot이 제한 조건서 인증) → **L4 고도자동(정해진 구역서 완전 무인 —
  로보택시의 필요선)** → L5 완전자동(어디서나 무인, 아직 아무도 도달 못 함).
- 판정 지표: 개입 없는 평균 주행거리, 인간 대비 사고율(인간 ≈ 1억 마일당 사망 1건이 기준선).

로보택시의 교훈(lesson): "자율주행이 안 돼서 못 하는 게 아니다. L4는 됐다. 벽은 한 도시씩
허가받고 지도를 만들고 보험 체계를 세우는 느린 확산이다." — 기술 완성과 대중 보급 사이의 간극.

### 4.2 AGI (범용 인공지능)

AGI는 사다리로 딱 떨어지지 않는 목표지만, 그것을 떠받치는 하드웨어·데이터·에너지에는
분명한 단계가 있다. **현재 병목은 알고리즘보다 "메모리 대역폭·전력·고품질 데이터"다.**

| 요소 | 사다리·임계 | 목표 | 현재 | 달성·선두 | 추진 | 벽(gap) |
|---|---|---|---|---|---|---|
| 연산 가속기(GPU) | 세대 (Ampere→Hopper→Blackwell→…) | 세대 지속 상승 | Blackwell(B200) 양산 | NVIDIA | AMD(MI300)·구글TPU·아마존Trainium | 공급·전력이 성능보다 제약 |
| 고대역폭 메모리 | HBM2→2E→3→3E→4 | HBM3E→HBM4 | HBM3E 양산, HBM4 진입기 | SK하이닉스(선두)·삼성·마이크론 | — | **핵심 병목** — GPU 성능이 아니라 메모리 대역폭·용량이 대형모델 한계 |
| 인터커넥트 | 노드 간 대역폭(NVLink·InfiniBand·이더넷) | 초대형 클러스터 | 수만~수십만 GPU 클러스터 상용 | NVIDIA·Broadcom | — | 스케일아웃 시 통신이 병목 |
| 학습 컴퓨트 규모 | 연 4~5배 증가 추세 | 지속 스케일 | 프론티어 모델 10^25~10^26 FLOP급 | OpenAI·Google·Anthropic·Meta | xAI 등 | 비용·전력이 스케일 상한을 규정 |
| 데이터 | 고품질 토큰 고갈 → 합성·멀티모달 | 지속 공급 | 웹 텍스트 사실상 소진, 합성데이터 전환기 | 프론티어 랩 전반 | — | 고품질 데이터 고갈 — 합성데이터 품질이 관건 |
| 알고리즘·추론 | 스케일링→추론(test-time compute) | 신뢰 가능한 추론 | 추론 모델 대두, 벤치마크 이동 중 | 프론티어 랩 | — | 벤치마크 포화 → 무엇을 "AGI 도달"로 볼지 정의 자체가 미정 |
| 전력·데이터센터 | 단일 캠퍼스 전력 규모 | GW급 | 수백MW→GW 계획 단계 | 하이퍼스케일러 | 원전·SMR 병행 검토 | **부상하는 병목** — 전력 조달이 물리적 상한 |

핵심 사다리 설명 — HBM(고대역폭 메모리) 세대:
- HBM2 → HBM2E → HBM3 → HBM3E(현 주력) → HBM4(진입). 세대가 오를수록 대역폭·용량이
  커져 더 큰 모델을 GPU에 올릴 수 있다. **AGI 경쟁의 실질 병목이 여기라, SK하이닉스가
  이 분야 선두라는 점이 반도체 투자에서 중요한 함의**를 갖는다.
- 판정 지표: 학습 컴퓨트 추이(Epoch AI, 기존 참조 가능), 프론티어 벤치마크(MMLU 포화 →
  ARC-AGI·SWE-bench·FrontierMath·GPQA로 이동 — "현역 벤치마크가 뭔지"가 곧 진척 신호).

AGI의 교훈(lesson): "AGI를 막는 건 아이디어 부족이 아니라 메모리·전력·데이터라는 물리적
자원의 벽이다. 소프트웨어 경쟁처럼 보이지만 실은 반도체와 전력 인프라 경쟁이다."

### 4.3 휴머노이드 로봇 (humanoid)

사람 모양 로봇이 공장·가정에서 일하려면 몸(액추에이터·전원)과 뇌(제어 AI)와 손(조작)이
모두 필요하다. **가장 어려운 건 걷기가 아니라 "손으로 물건을 다루는 것"과 "대당 원가"다.**

| 요소 | 사다리·임계 | 목표 | 현재 | 선두·추진 | 벽(gap) |
|---|---|---|---|---|---|
| 보행·균형 | 정적→동적 보행→험지 | 동적 보행 | 도달(데모 수준) | Boston Dynamics·Unitree | 데모는 됐으나 신뢰성·연속가동 미흡 |
| 손·조작(manipulation) | 정밀 파지·양손 협응 | 범용 조작 | 제한적 | Tesla·Figure | **최대 기술 병목** — 다양한 물체를 사람처럼 다루기 |
| 제어 AI | 스크립트→학습기반→VLA모델 | 범용 VLA | 전환기 | Figure·Tesla·NVIDIA(정책모델) | 시뮬→실물(sim-to-real) 격차 |
| 전원·구동 | 배터리 밀도·액추에이터 효율 | 종일 가동 | 수시간 | 전반 | 가동시간·발열 |
| 대당 원가 | $/대 (연속량) | <$2만(대량보급선) | 수만~십수만 $ 추정 | Tesla(저가 목표)·Unitree(저가 노선) | **보급 병목** — 양산 규모 이전 |

판정 지표: 연간 출하량(아직 추정치 시대 — 출처 명시 필수), 대당 가격, 감속기·액추에이터
등 부품 기업 매출. 센서·AI 컴퓨트는 로보택시·AGI와 공유 자산.

휴머노이드의 교훈: "두 발로 걷는 건 이미 됐다. 어려운 건 사람 손의 섬세함과, 한 대에
수천만 원을 수십만 원으로 낮추는 일이다."

### 4.4 기타 기술 — 사다리 요약 (개발 시 확장)

- **핵융합 상업 발전**: 사다리 = 과학적 손익분기(Q>1, NIF 2022 달성) → 공학적 손익분기 →
  실증 발전 → 상업 발전. 현재 공학적 손익분기 이전. 벽 = 연속 가동·재료·비용.
  판정 지표 = Q값·민간 누적 투자(FIA).
- **우주 상업화**: 사다리 = 재사용 로켓(달성, SpaceX) → 발사비용 $/kg 하락(연속량,
  목표 <$1000, 현재 개선 중) → 궤도 인프라. 벽 = 발사 빈도·비용의 추가 하락.
- **유전자 치료 보편화**: 사다리 = 개념증명 → 개별 승인(진행, CRISPR 기반 첫 승인들) →
  다질환 확대 → 대중 보급. 벽 = 치료당 비용(수억~수십억 원)과 전달 기술.
