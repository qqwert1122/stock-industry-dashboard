# 기능 설계 — '미래' 메뉴 (F1~F3) [Tier 2]

상태: 기획 확정 대기 (2026-07-10). 목적: **기술을 잘 모르는 일반인**이 "우리가 나아갈 미래가
어떤 모습이고, 지금 어디까지 왔는지"를 확인하고 **지속적으로 관찰**할 수 있는 페이지.
『마침내 특이점이 온다』의 연도별 기술 예측을 출발점으로, 예측 → 현재 진척 → 추진 기업을
하나의 타임라인으로 묶는다.

의존성: 데이터는 전부 신규 YAML + 기존 파이프라인 재활용이라 즉시 가능. 프론트는 현행
2단 네비(navRoot: overview/market/industry) 위에 4번째 루트를 추가한다. F3의 변화 피드는
H1(시그널 이력) 머지 후.

공통 제약: **운영 비용 0원** (README 공통 지침). 신규 유료 API 없음.

---

## 0. 제품 관점 — 이 문서의 모든 결정 기준

기존 메뉴(시황·지표)가 "투자자의 오늘"이라면, '미래'는 **"일반인의 10년"**이다.
독자는 AGI·TRL·L4 같은 용어를 모른다는 전제로 설계한다.

사용자가 이 페이지에서 답을 얻어야 하는 질문 3가지:

1. **어떤 미래가 오고 있나?** — 연도별로 무슨 기술이 온다고 예측되는가
2. **지금 어디까지 왔나?** — 그 기술이 공상인지, 실험실인지, 이미 내 옆에 있는지
3. **지난번 봤을 때보다 뭐가 달라졌나?** — 재방문할 이유 (이 페이지의 성패를 가르는 질문)

설계 원칙:

- **설명 우선**: 모든 기술 카드의 첫 문장은 전문용어 0개로 읽혀야 한다. 숫자·차트는 그 다음.
- **모든 주장에 지표**: "가까워지고 있다"는 말은 반드시 관찰 가능한 시계열과 함께 나온다.
- **정직한 불확실성**: 예측은 사실이 아니라 출처 있는 의견이다. 예측 주체를 항상 명시하고
  ("커즈와일은 2029년으로 본다"), 달성/미달성 이력을 숨기지 않는다.
- **투자 정보는 보조**: 기업 지표는 "이 미래에 돈이 실제로 움직이고 있다"는 증거로 배치한다.
  종목 추천 뉘앙스 금지 — 기존 브리핑 디스클레이머와 동일 원칙.

## 1. IA — 상위 메뉴 4번째 루트

- `renderFilters()`(templates/dashboard.html)의 루트 메뉴에 `data-nav-root="future"` 추가:
  종합 / 시황 / 지표 / **미래**.
- '미래' 진입 시 사이드 메뉴 = 분야 필터: 전체(기본) · AI · 로봇·모빌리티 · 바이오 ·
  에너지 · 우주. 별도 하위 페이지 없이 타임라인 단일 뷰를 필터링한다.
- 해시 라우팅은 ia-consistency.md B1.1 규칙을 따른다: `#/future`, `#/future/{tech-id}`.

## 2. 화면 설계

### 2.1 타임라인 뷰 (기본 화면)

세로 타임라인(위=현재, 아래=미래) + 상단 연도 미니맵. 확정된 구성:

1. **연도 미니맵** (상단 고정): 오늘~2045 가로 축. 점 클릭 시 해당 구간으로 스크롤,
   스크롤에 따라 현재 위치 하이라이트. 모바일에서는 기존 카테고리 칩 바 위치 문법.
2. **"오늘" 마커가 앵커**: 타임라인이 "예측 목록"이 아니라 "지금 우리가 어디 있는가"로
   읽히게 한다. 오늘 위쪽에는 **이미 달성된 과거 예측**을 회색+체크로 접어 표시
   (예측 출처의 신뢰도를 독자가 체감하는 장치).
3. **연대 밴드**: 2030년대부터는 연도 단위가 아닌 밴드("2030년대")로 묶는다.
   먼 예측일수록 해상도를 낮추는 것이 정직하고, 타임라인 길이도 통제된다.
   밴드 헤더는 `position: sticky`.
4. **기술 카드 3층 구조**:
   - 예측: 기술명 · 분야 · 예측 연도 · **쉬운 설명 첫 문장** (2.3절)
   - 진척: 핵심 지표 2~3개 스파크라인 + **병목 한 줄 배지** ("병목: 규제·보험 TRL 4")
   - 기업: 관련 기업 티커 칩 + 당일 등락률
5. **최근 변화 배지**: changelog(2.4절)에 30일 내 기록이 있으면 카드 모서리에
   "NEW — 3월: 규제 TRL 4→5" 배지.

### 2.2 기술 상세 (카드 펼침, `#/future/{tech-id}`)

섹션 순서가 곧 서사다 — **이야기 → 구조 → 근거 → 돈** 순서:

1. **쉬운 설명** (2.3절 3문 구조 전체)
2. **의존 순서도**: 요소 기술 → 통합 → 목표(예측 연도)로 수렴하는 좌→우 DAG.
   노드 색 = TRL 밴드 (상용 7–9 / 실증 4–6 / 연구 1–3), **병목 노드는 경고색 +
   목표로 가는 간선을 점선**으로 — "이것만 뚫리면 된다"가 그래프의 끊긴 자리로 보인다.
   노드 5~8개, 간선은 필수만 (스파게티 방지). 위상 정렬로 열 배치, 라이브러리 없이 SVG.
   모바일은 상→하로 회전.
3. **요소 기술 TRL 스택**: 순서도의 각 노드를 행으로 — TRL 9단계 세그먼트 바 +
   판정 근거 한 줄(출처 링크) + 연결 지표 + 관련 기업 칩. 병목 행은 경고색 배경.
   다른 미래 기술과 공유하는 요소는 "🔗 휴머노이드와 공유" 칩 → 클릭 시 해당 기술로.
4. **진척 지표 차트**: 기존 지표 디테일 패널과 동일 문법 (long_history 재사용).
5. **관련 기업**: 주가 스파크라인 + (있으면) CapEx/R&D. sec_capex 문법 재사용.

### 2.3 설명 레이어 — 이 기획의 차별점

모든 기술(technology)과 요소 기술(component)은 **3문 구조**의 설명을 필수로 가진다.
기존 metrics의 `meaning` 필드와 같은 역할, 같은 톤:

| 필드 | 질문 | 예시 (로보택시) |
|---|---|---|
| `what` | 이게 뭔가? (비유 1개 허용) | 운전기사 없이 스스로 달리는 택시입니다. 스마트폰으로 부르면 빈 운전석의 차가 데리러 옵니다. |
| `why` | 내 삶이 어떻게 바뀌나? | 이동 비용이 크게 내려가고, 운전을 못 하는 노인·어린이의 행동반경이 넓어집니다. 차를 소유할 이유 자체가 줄어들 수 있습니다. |
| `now` | 지금 어디까지 왔나? (한 문장) | 미국 14개 도시에서 이미 유료 운행 중이지만, 규제와 보험 제도가 확산 속도를 정하고 있습니다. |

**용어 사전(glossary)**: TRL, AGI, L4, CapEx 같은 불가피한 용어는 점선 밑줄 칩으로 표시,
탭/호버 시 툴팁 풀이. `data/future/glossary.yaml`로 관리하고, 본문 자동 링크는 하지 않는다
— 카드당 최대 3개를 콘텐츠에서 수동 지정 (밑줄 범벅 방지).

### 2.4 지속 관찰 장치 — "다시 올 이유"

정적 백과사전이 되는 순간 실패다. 변화를 1급 데이터로 다룬다:

- **changelog가 데이터다**: TRL 승급/강등, 예측 달성, 병목 교체, 지표 임계 통과를
  `data/future/changelog.yaml`에 날짜·근거와 함께 기록. 이 파일이 곧 "미래가 오고 있다"는
  증거의 축적이다.
- 타임라인 상단 **요약 배너**: "올해: 달성 1건 · TRL 승급 3건 · 새 병목 1건" (있을 때만).
- 카드/행 단위 **NEW 배지**: 30일 내 changelog 항목 표시.
- (F3) **H1 시그널 이력 연계**: Drawer 알림 피드에 `future` 이벤트 타입 추가.
- (F3) **브리핑/텔레그램 연계**: changelog 신규 항목 발생 시 아침 리포트에 한 줄
  ("어제 캘리포니아가 무인주행 보험 기준을 확정 — 로보택시 병목 TRL 4→5").

## 3. 데이터 모델 — `data/future/`

콘텐츠=코드 원칙: 모든 TRL 판정과 예측에는 `source`(URL)와 `as_of`(판정일)가 필수.
근거 없는 숫자는 빌드 검증에서 경고.

```yaml
# technologies.yaml — 미래 기술 (타임라인의 카드)
- id: robotaxi
  name: 로보택시
  category: 로봇·모빌리티
  predicted: { year: 2027, source_label: 커즈와일 『마침내 특이점이 온다』, source: "https://..." }
  status: upcoming          # achieved | upcoming | distant
  what: 운전기사 없이 스스로 달리는 택시입니다. ...
  why: 이동 비용이 크게 내려가고, ...
  now: 미국 14개 도시에서 이미 유료 운행 중이지만, ...
  glossary: [trl, l4]       # 이 카드에서 툴팁을 붙일 용어 (최대 3)
  components: [av-software, sensor-stack, v2x, vehicle-cost, av-regulation]
  bottleneck: av-regulation
  metrics: [waymo-rides, av-cities]        # 카드 스파크라인용 (최대 3)
  companies: [GOOGL, TSLA, UBER]

# components.yaml — 요소 기술 (여러 미래 기술이 공유하는 독립 엔티티)
- id: av-regulation
  name: 규제·보험 체계
  what: 사고가 났을 때 누가 책임지는지를 정하는 법과 보험의 약속입니다.
  why: 기술이 완성돼도 이 약속이 없으면 도로에 나올 수 없습니다.
  trl: 4
  trl_note: 미국 주 단위 부분 허용, 연방 기준 부재
  as_of: 2026-07-10
  source: "https://..."
  depends_on: []            # 순서도 간선
  metrics: [av-cities]
  companies: []

# glossary.yaml — 용어 사전
- id: trl
  term: TRL (기술성숙도)
  short: 기술이 아이디어(1)에서 일상 제품(9)까지 어디쯤인지 나타내는 NASA의 9단계 눈금입니다.
  source: "https://www.nasa.gov/..."

# changelog.yaml — 변화 기록 (관찰의 핵심 데이터)
- date: 2026-03-14
  tech: robotaxi
  component: av-regulation
  type: trl_up              # trl_up | trl_down | achieved | bottleneck_change | milestone
  from: 3
  to: 4
  note: 캘리포니아 무인주행 상업 운행 보험 기준 확정
  source: "https://..."
```

빌드 산출: `site/data/future.json` — technologies + components 병합, metrics는
기존 `history_key` 참조로 연결(시계열 중복 저장 없음), changelog 최근 24개월분 포함.

## 4. 진척 지표 소싱 (비용 0원)

원칙: 자동 재활용 > 반자동(연·분기 스크립트) > 수동 YAML. 새 지표는 기존
`collect_*_metrics` 문법으로 추가해 '미래' 밖(해당 산업 메뉴)에서도 보이게 한다.

| 지표 | 소스 | 방식 |
|---|---|---|
| 기업 주가/등락률 | Yahoo chart (기존) | **자동 — 재활용** |
| 빅테크 CapEx, R&D | SEC EDGAR (기존 sec_capex 확장) | **자동 — 재활용** |
| 반도체 판매액, 로봇·우주·배터리 산업 지표 | 기존 metrics | **자동 — 교차 참조만** |
| AI 학습 컴퓨트 추이 | Epoch AI 공개 CSV | 반자동 (분기 1회) |
| FDA 신규 치료제 승인 건수 | FDA 공개 데이터 | 반자동 (연 1회) |
| 로켓 발사 횟수 | 공개 발사 기록 DB | 반자동 (분기 1회) |
| Waymo 운행 규모, 무인주행 허가 도시 수 | 공식 발표 수집 | **수동** (분기, changelog와 함께) |
| TRL 판정 | 큐레이션 | **수동** (반기 전수 리뷰 + 수시 changelog) |

수동 항목은 `as_of`가 180일을 넘으면 /admin(fetch_log)에 스테일 경고.

## 5. 콘텐츠 작성 가이드 (톤)

`what/why/now`와 glossary 작성 규칙 — 리뷰 시 이 기준으로 반려한다:

1. 중학생이 한 번에 읽고 이해하는 문장. 한 문장 40자 내외, 필드당 2문장 이내.
2. 첫 문장(`what`)에 전문용어 금지. 용어가 불가피하면 glossary 칩으로만.
3. 비유는 필드당 1개까지. 정확성을 해치는 비유면 뺀다.
4. 과장 금지: "세상을 바꿀", "혁명" 금지. 어조는 광고가 아니라 관찰 —
   "~입니다 / ~하고 있습니다"로 현재 상태를 서술.
5. 예측은 항상 주체와 함께: "커즈와일은 2029년으로 예측합니다" (O),
   "2029년에 옵니다" (X).
6. 리스크·반론 한 줄 권장: `now`에 확산을 막는 요인을 담는다 (병목과 자연 연결).

초기 콘텐츠 스코프 (기술 8개): AGI(2029) · 로보택시(2027) · 휴머노이드 로봇(2030년대 초) ·
수명 탈출 속도(2032) · 유전자 치료 보편화(2030년대) · 핵융합 상업 발전(2030년대 후반) ·
우주 상업화(진행 중) · 특이점(2045, 종점 표식). 요소 기술 약 15개 예상 (공유 포함).
